# Review guide

`cagr review` reads this file into every review. Say what matters in this repo and what does not.

## Always check

- Errors are handled where they happen, or passed up with context. Nothing fails silently.
- New behavior has a test that would fail if the code broke.
- Inputs from users, files and the network are checked before use.

## Important here

- Hooks fail open. An error inside cagr must let the agent's call through and tell the human, never block it or crash with a stack trace. Check `src/hook/run-hook.ts` and every new path a hook can take.
- Every block or deny message says what to do instead. A message that only says "no" is a bug.
- Time budgets: `command.before` under 50ms (no network, no slow git calls, no reading large files), `file.after_edit` under 1s, `turn.end` under 60s.
- Command matching in `src/guards/` and `src/shell.ts`: a guard that can be dodged by quoting, `&&`, a subshell or an env prefix is a real bug. So is one that fires on text inside a quoted string or heredoc.
- Generated files (`.claude/settings.json`, `.codex/hooks.json`, `.githooks/*`, the GitHub workflow) must keep the user's own entries and stay stable across runs, or `sync --check` drifts.
- The review pipeline must not let the gate open on stale state: a record for an older commit, a finding marked fixed without evidence, or a reviewer error treated as a pass instead of a notice.

## Skip

- `schema/cagr.schema.json` is generated by `bun run schema`.
- `dist/` and `bun.lock`.
- Style and formatting: Biome handles them.
