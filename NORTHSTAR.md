# North Star

guardwright should give any repo, with one config file, the review pipeline described in [How the Claude Code team does code review](https://claude.dev/blog/solving-code-review-at-anthropic/). Every part that can live in a repo is guardwright's job. The rest belongs to the platform (GitHub settings, feature flags, release channels) and the team. For those parts, guardwright checks that they are switched on and says how to fix them when they are not.

The test: a team runs `guardwright init` and `guardwright sync`, commits the result, sets one secret, and has the post's pipeline. Agents cannot open a pull request that has not been reviewed. Agents cannot approve or merge their own work. CI runs the same checks the agent ran. Every review finding gets an answer.

## The pipeline, layer by layer

Status: **done** means built and tested here. **built** means built and tested against a fake `gh`, but not yet run against a live GitHub. **platform** means outside the repo: guardwright only checks it, or leaves it alone.

| Layer in the post                                                                 | guardwright                                                                                                                                                                              | Status   |
| --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| **1. Verified before anyone looks**                                               |                                                                                                                                                                                          |          |
| Formatter and linter hooks                                                        | `on_edit` runs on each edit, changed files only                                                                                                                                          | done     |
| The agent runs tests and the build and shows the output                           | `on_turn_end` blocks the stop while checks fail, with up to 3 tries                                                                                                                      | done     |
| Recurring findings move into a lint rule                                          | ast-grep rules with `instead` and tested examples                                                                                                                                        | done     |
| A fresh-context review before the PR                                              | `guardwright review` starts a reviewer agent (Claude Code or Codex) in a fresh context, read-only, with the repo's `REVIEW.md`                                                           | done     |
| `CLAUDE.md` and `REVIEW.md`                                                       | `REVIEW.md` is read into every review. `init` writes a starter                                                                                                                           | done     |
| **Gate**: the agent may not open a PR without a review                            | `gh pr create` and `gh pr ready` are denied until the current commit has a review with no open Important finding                                                                         | done     |
| **2. AI review on every PR**                                                      |                                                                                                                                                                                          |          |
| Reads the diff against the repo and the PR's intent                               | The prompt carries the diff, the commit messages and the risk tier. The reviewer reads any file it needs                                                                                 | done     |
| Quick, Standard, Deep                                                             | `[review] effort`. A high-risk change is always reviewed at Deep                                                                                                                         | done     |
| Several finders, a vote, then post                                                | Standard: a bug finder and a security finder, then a verifier. Deep: three finders, then three verifiers, keeping a finding when at least two agree                                      | done     |
| Drop style-only findings                                                          | Findings in the `style` category are dropped                                                                                                                                             | done     |
| Important, Nit, Pre-existing tags                                                 | Every finding carries one                                                                                                                                                                | done     |
| Every finding is answered                                                         | Fix it and the next round marks it fixed, or `guardwright review answer <id>` with a reason. The gate and CI stay red until then                                                         | done     |
| Comments on the PR                                                                | `guardwright review --ci` posts a review with inline comments and keeps its state in the PR                                                                                              | built    |
| **3. Security review that blocks**                                                | A security finder in every Standard and Deep review. Its findings block like any Important one                                                                                           | done     |
| **4. Required CI**                                                                |                                                                                                                                                                                          |          |
| Lint, types, tests, build                                                         | `guardwright ci` runs the same `on_edit`, `on_turn_end` and rules the agent ran, plus commit and branch names. It writes GitHub annotations and a summary                                | done     |
| PR template with Testing, Risk, How to revert                                     | `sync` writes it. `gh pr create` is denied when the body lacks those headings, and `ci` checks the body                                                                                  | done     |
| The workflow                                                                      | `sync` writes `.github/workflows/guardwright.yml`: checks, review, and the merge queue trigger                                                                                           | built    |
| **5. Human approval by risk**                                                     |                                                                                                                                                                                          |          |
| The change sets the tier                                                          | `[risk]` globs give each file a tier, and the change takes its highest. `guardwright risk` prints the tier, the approvals it needs, and the owners                                       | done     |
| Sensitive paths and CI workflows always need a person                             | The `recommended` preset marks `.github/workflows/**` high. `sync` writes `CODEOWNERS` from `[risk]` owners                                                                              | done     |
| An agent's approval never counts                                                  | `gh pr merge`, `gh pr review --approve` and the merge API are denied for agents                                                                                                          | done     |
| Approvals cover one commit, threads must be resolved                              | `doctor --github` checks branch protection: required reviews, stale approval dismissal, code owner review, conversation resolution, required checks                                      | built    |
| A classifier picks the tier                                                       | Globs, not a model. A model classifier can plug in later                                                                                                                                 | partial  |
| Trusted authors get lighter paths                                                 | Platform: CODEOWNERS and branch protection                                                                                                                                               | platform |
| **6. Merge queue, flags, staged release**                                         | The workflow runs on `merge_group`, and `doctor --github` checks that a merge queue is on. Flags and release channels are the team's own                                                 | partial  |
| **7. Detection and rollback**                                                     | Platform: on-call, dashboards, reverts                                                                                                                                                   | platform |
| **Making the reviewer better**                                                    |                                                                                                                                                                                          |          |
| Incidents become evals                                                            | `.guardwright/review-evals/*.toml` hold past bugs (a commit range and where the bug was) and clean changes. `guardwright review eval` scores the reviewer and compares with the last run | done     |
| Noise measured by what people did                                                 | Each answer is recorded as wrong, intentional or minor. `guardwright review stats` reports them                                                                                          | done     |
| Convergence: a round cap, diff-only re-review, no repeats, flagging the bug class | After round 1 the reviewer sees only the new commits plus the open findings. Posted findings are never repeated. After `max_rounds` it tells the author to step back                     | done     |
| Rounds-to-pass                                                                    | `review stats`: share passing in one round, share needing five or more, mean rounds                                                                                                      | done     |
| Nightly review of old code                                                        | `guardwright review --scan <globs>` reviews existing code. The workflow can run it nightly and open an issue                                                                             | built    |

## Rules that hold everything up

- Every block says what to do instead.
- Hooks fail open. A broken reviewer, a missing CLI or a network error never traps an agent: the gate tells the agent and the human what failed and how to get past it.
- An answer is always possible, so a review can always finish: fix the finding, or answer it with a reason that a human will read.
- The hook budgets stay: the gate reads one file and makes two quick git calls, about 25ms on the compiled binary.

## Out of reach for a library

Feature flags, `latest` and `stable` release channels, on-call, revert dashboards, and circuit breakers that tighten approval when those numbers move. Teams own these, and the post lists them as practice, not tooling.
